# ProjectManager v0.11.0

_2026-08-20 · changes since pm-v0.10.0_

## Features
- Deploy straight from the Sites list: every row now has a CMS version picker
  (latest preselected; older versions can't be chosen) and a Deploy/Redeploy
  button — no more visiting each site's Deployment section.
- Fleet rollouts: select any set of sites (or all of them) and deploy one CMS
  version to the whole selection. A preflight dialog shows exactly what each
  site will do — install, upgrade, move off an untagged build, or be skipped —
  with a total time estimate before anything runs.
- Rollouts are upgrade-only: sites already on the target version or newer are
  skipped automatically. Rolling back means cutting a new tag, never downgrading.
- Configurable parallelism (1–10 builds at once): the rest of the sites queue
  server-side and start as build slots free up, surviving page reloads.
- Live rollout monitor above the list: progress, building/queued/deployed/
  failed/skipped counts, per-row queue badges, and Pause / Resume / Stop
  controls. Failed sites can be retried in one click when the rollout ends.
- Circuit breaker: three consecutive failures pause the rollout automatically
  so a broken release can't sweep the fleet; running builds finish and report.

## Other
- The deploy dispatch core is now a shared library used by both the per-site
  deploy and the rollout engine; single-site behavior is unchanged.
- All new UI ships in English, Finnish, and Estonian, with parity tests
  guarding the new error strings.
