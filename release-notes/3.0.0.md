# CMS v3.0.0

_2026-08-18 · changes since r-2.9.0_

## Breaking
- **API keys are gone.** The remote MCP server (`/mcp`) no longer accepts `Authorization: Bearer bzb_…` keys, and Settings → MCP no longer mints them. Any Claude Code / `.mcp.json` entry that carried a key must drop the header — after this release the client authenticates with OAuth instead (see below). The `api_key` table is dropped on migration.

## Features
- **OAuth 2.1 sign-in for MCP.** Each site is now its own authorization server: add just the site's `/mcp` URL to Claude Code (no secrets, safe to commit), run `/mcp` → Authenticate, and the browser opens the site's new consent page. You sign in with your normal CMS account (password, Google, or "Sign in with BizbeeCMS") and approve; the client acts *as you*, bounded by your role. Tokens are short-lived with rotating refresh, PKCE-bound, and hashed at rest.
- **Consent page** (`/oauth/authorize`) shows who is asking, which account will be acting, what that allows, and where the request returns. Signed-out visitors get the site's login page in place and land back on the request afterwards.
- **Settings → MCP** now lists your authorized clients (created / last used / expiry) with one-click revoke, plus copy-pasteable Claude Code wiring for this site.

## Other
- OAuth and MCP responses are stamped `private, no-store` at the edge and excluded from link localization.
